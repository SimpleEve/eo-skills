# 提问纪律（单一来源）

> 被 eo-change / eo-brainstorming / eo-design 引用。目标：把提问从「反复澄清直到 95% 确信」的轰炸，变成有预算、有台账、有节奏的推进。

## 1. 事实自查，决策上抛

**能从代码 / state / agent-handbook / lessons / git 历史查到的信息，禁止问用户。** 提问前先把可自答的问题消化掉。只把真正的**决策**（多种合理选择、无明显默认值、影响后续形态）交给用户。

## 2. 提问预算（按复杂度配比）

| 定级 | 判断信号 | 澄清预算 |
|------|---------|---------|
| trivial | 纯样式/文案/翻译/显而易见小修 | 0-1 问（通常直接短路，见 granularity.md） |
| simple | 单一能力点、边界清晰 | 1-3 问 |
| complex | 多能力点、有方案权衡 | 3-5 问 |
| critical | 方向未定、影响架构 | 5+ 问，**并建议升级 /eo-brainstorming** |

每轮最多 1-2 问。预算内问不完的：有合理默认 → 用默认并显式标注「（假设）」；无默认 → 记入 defer（见 §3），**defer 全篇上限 3 条**。

## 3. 决策台账（钉住前置结论）

内部维护三态清单，**不渲染给用户**：

- **已钉（locked）**：结论 + 一句理由。已钉项不得重问、不得被后续讨论隐式推翻；发现冲突必须显式提示「这和之前钉的 X 矛盾」。
- **未钉（open）**：待拍板的决策面，按 upstream 优先（结论影响最多下游的先问）。
- **defer**：用户推迟的决策，写入产出文档的「开放问题」节。

已钉决策最终落入 change.md §1（来自 brainstorming 捕获的直接继承，不重问）。

## 4. 问法

- **封闭选择协议（runtime 中立）**：优先使用当前 runtime 的结构化提问工具（Claude Code 为 AskUserQuestion）；runtime 无此类工具时，在对话中列出 2-4 个编号选项并等待回复。无论哪种形式：必有一个选项标注推荐 + 一句理由，用户只需选一下。下文各 skill 说「按封闭选择协议」即指本条。
- **开放问题走正文**，放在消息末尾，一次 ≤2 个。
- **UI/UX 类问题**：文字难以描述效果时，在选项末尾追加「生成 HTML 对比页帮你决策」——自包含 HTML、真实内容、可并排对比；产物放 `tmp/eo/`（见 conventions.md），结论回填决策台账。

## 5. 疲劳信号识别

用户说「别问了 / 先做吧 / 就这样 / 你定」→ **立即停止提问**，用合理默认推进，全部假设显式写入产出物并标注「（假设）」。

## 6. 提问反模式表

| ❌ 反模式 | ✅ 正确做法 |
|----------|-----------|
| 一条消息塞 3+ 个问题 | 每轮 1-2 问，按 upstream 排序 |
| 问代码/文档里能查到的事实 | 先自查，只上抛决策 |
| 重问已钉结论 | 查台账，冲突时显式提示 |
| 不给选项的抽象大问题（"你觉得架构怎么设计？"） | 给 2-4 个具体候选 + 推荐项 |
| 用"可能/应该"带着假设继续而不声明 | 假设必须显式标注「（假设）」 |
| 澄清结束不做覆盖确认 | 收尾问一次「还有遗漏的关注点吗」 |
