# 交付证据面（evidence.md）规范（单一来源）

> 被 eo-implement（产）/ eo-fix（刷新）/ eo-archive（硬门 + 渲染）/ eo-loop（收尾渲染）引用。定位：回答用户「做了什么、做到哪一步、去哪看、怎么验」。与 acceptance.md 的分工——验收单管「人工逐项勾选」，证据面管「入口 + 证据 + 验收指引」的展示。证据在**生产时捕获**（implement 起环境自验的当下，环境是活的、截图是新的），归档时只渲染不重建（Proof 第三层见 [goal-contract.md](goal-contract.md)）。

## 何时存在

- **每个 change 必产**：eo-implement 全部 TODO 完成时生成，不以人工 AC 为前提（这是与 acceptance.md「无人工项不生成」的关键差异）
- 位置：`eo-doc/changes/<change-id>/evidence.md`，随 change 归档冻结为证据历史
- **最薄形态**：无可观察面的 change（纯重构等）三段各一行，不豁免、不设分支

## 模板

```markdown
# 交付证据 — <change 标题>

## 入口与环境
<可访问地址（URL / 端口）或启动命令；服务状态（已起 / 如何重启）；所需账号 / 测试数据的获取方式。无需环境写「无」>

## 过程证据
<截图相对路径（shots/...）或关键输出摘要（命令 + 关键输出）。UI 变化必附截图>

## 怎么验
<人工项 → 指 acceptance.md 对应项；自动项 → 一句证据摘要 + 指针（test.md / 自验速报要点）>
```

最薄形态可压成三段各一行，字段语义不变。

## 类型预设（可扩展）

出厂四套预设，生成时按 change 形态选用，填充各段的类型特异要点：

| 预设 | 入口与环境 | 过程证据 |
|------|-----------|---------|
| web | dev / test server URL、端口、账号获取方式 | 关键页面与流程截图 |
| cli | 命令与参数、示例输入 | 关键输出摘录 |
| service | 服务地址 / 端口、健康检查、依赖服务 | 请求-响应样例、日志摘录 |
| library | 引入方式、最小调用示例 | 示例运行输出 |

**项目扩展规则**：项目可在 `eo-doc/templates/` 放 `evidence-<type>.md`——与出厂预设同名即覆盖，新名即新增类型；eo-implement 生成证据面前先查项目模板，命中优先于出厂预设。

## 截图纪律（硬性）

- UI 变化的批末自验必留截图，存 change 目录 `shots/`（命名 `<批号>-<场景>.png`），随归档冻结进 git，作审计历史
- evidence.md 用相对路径引用（`shots/...`）
- 非 UI change 不留截图，过程证据写关键输出摘要

## 刷新与失效（硬性）

修复循环（/eo-fix 循环内分支）或 /eo-fix 落点记账改变了入口 / 行为 / 截图事实时，同步刷新 evidence.md 对应段，截图过时重拍。失效判定语义对齐 [acceptance.md](acceptance.md)「失效与重置」：影响范围判不清 → 整份重核。

## 生命周期

| 环节 | 责任 |
|------|------|
| eo-implement 全部完成 | 生成 evidence.md（先查项目 `eo-doc/templates/evidence-*.md`，命中优先）；速报带路径 |
| /eo-fix（含循环内分支） | 按「刷新与失效」更新对应段 |
| eo-archive（硬门） | 核对存在且三段非空——缺失 / 空段 = 校验失败，三选一（补齐 / 显式豁免 / 终止），不静默放行；交付汇报中渲染（引内容，不重建） |
| eo-loop | 线段收尾的交付汇报引 brief + evidence.md 渲染 |
