# jev 判定门：System One 独立复判（单一来源）

> 被 eo-change（风险信号播报）/ eo-change-review（维度 6）/ eo-fix（卡点检查）引用。jev = TypeSafe 的 System One 判定模型：state + typed questions → 结构化 JSON（boolean = P(true)、choice = 选项 + 概率分布、score = 概率加权）。**不能生成文本**，问题间并行独立评估。CLI = `jev-cli`（配置 `~/.jev-cli/config.yaml`，key 取 `TYPESAFE_API_KEY` 环境变量或 config）。

## 定位


**决策辅助，不是基底**：jev 不执行节点、不写代码、不产工件文本。它只在两个判定点提供**结构性独立的第二判定**——与执行/起草 LLM 零共享会话上下文，不继承其推理先验。价值时刻 = 现行流程里「LLM 自判一遍、无第二双眼」的位置。**独立性的另一半在 state**：喂给 jev 的 state 只含原始证据（意图、AC、失败事实），**剥离一切前序判定记录**（§6 风险登记、豁免、复审结论、根因叙述）——带着别人的结论去问，得到的只是复读。

1. **只判不写**：jev 输出只影响走哪条分支，**不生成叙述性文本**（报告结论、播报表述仍由执行 LLM 写）。允许的唯一例外 = 带出处标注的分支结论行（如 `卡点检查：<根因>（jev 预判，P=0.81，<版本>），<日期>`）——这是把 jev 的 typed 结论连同概率出处一并**由执行 LLM 转录**，不是让 jev 写文。该行是 change.md 里的**过程注记**（与「熔断豁免」同类），**不进 frontmatter、不改 status**——状态真相仍只在 frontmatter 与报告（conventions §3），且受「jev 预判证伪」条款回收
2. **state 最小化 + 脱敏**：只给判定所需的工件节选（意图 / AC / 失败事实），不整篇灌；组装时**剥离密钥、token、凭证等敏感串**，且按「定位」节要求剥离前序判定记录
3. **fail-open**：探测不过、API 失败、超时、输出不可解析 → 一律回退现行路径，主路永不因 jev 阻塞。**降级不可静默**：照常播报一句「jev 复判未执行」（不追问用户，但必须让用户看得见复判失效——静默失效 = 复判形同虚设时无人知晓）
4. **阈值集中本文件**：挂钩点只写「按 jev-gate 阈值消费」，不散落数值
5. **探测零网络、有界**：`command -v jev-cli && jev-cli doctor --offline`（exit 0 = 可用），探测本身包 ≤5s 超时（macOS 用 gtimeout 或等价）——doctor 挂起也按不可用降级，未装是常态，静默降级（此处「静默」指不打扰，播报仍按第 3 条注明）
6. **调用形态**：state 与 questions 一律落临时文件（0600 权限，用完即删）传引用——`jev-cli eval --state-file <tmp> --questions-file <tmp> --timeout 30000 --compact`，**禁止 `-s "<state>"` 内联插值**（change 内容可含 `$()`/反引号/引号，shell 展开即注入或静默截断）；`--timeout 30000` 是命令行原生参数，必须带上，不得只靠 prose 约定。exit 0 = 成功；1 = provider/网络失败；2 = 问题非法；3 = 凭证缺失——非 0 一律按 fail-open 处理
7. **版本留痕**：播报注明本次所用 jev 模型版本（jev-latest 是漂移别名，阈值校准依赖可比性）

## 挂钩点 1 · 风险信号独立复判

**消费方**：eo-change 第四步（确认前播报）、eo-change-review 维度 6。信号清单唯一来源仍是 [granularity.md](granularity.md) §5。

**痛点**：§5 自己承认「信号漏判是本清单的最大软肋」——现行只有起草 LLM 自判一遍，漏判无第二道防线。

**state**：change.md §1 意图 + §2 AC 标题行（≤80 行节选）。**不含 §6 风险与开放问题节**——那是起草方的判定记录，喂给 jev 会把复判锚定成复读（维度 6 的比对对象是 §6 登记，不是 jev 的输入）。

**questions**（三个语义类信号各一 boolean；「AC ≥5 / 触及 ≥3 共享模块」机械可数，不问）：

```json
{
  "irreversible": {"type": "boolean", "instructions": "该变更是否包含不可逆操作（删数据 / schema 变更 / 破坏性 API / 无法回滚的迁移）？", "criteria": {"true": "存在任一回滚不了或回滚代价极高的动作", "false": "全部动作可逆"}},
  "security_boundary": {"type": "boolean", "instructions": "该变更是否触及权限、资金或安全边界（鉴权 / 授权 / 支付 / 转账 / 密钥 / 用户敏感数据）？", "criteria": {"true": "任一相关路径被新增或修改", "false": "不触及"}},
  "external_contract": {"type": "boolean", "instructions": "该变更是否依赖或修改外部契约（第三方 API、平台规则、协议格式、外部数据源结构）？", "criteria": {"true": "存在外部契约的依赖或变更", "false": "纯内部逻辑"}}
}
```

**消费**（三档，与 §5「判不准按命中处理」「升级是便宜的、漏判是贵的」同向）：

- **P(true) ≥ 0.7** → jev 命中该信号（高置信）
- **0.4 ≤ P(true) < 0.7** → 低置信，**按命中处理**并在播报标注 `jev 低置信提示 P=<值>`——边界区间正是「判不准」，判不准按命中
- **P(true) < 0.4** → jev 未命中
- 与执行 LLM 自判**取并集**（任一命中即命中；jev 只增不减，不推翻自判的「判不准按命中」）
- 播报注明两判来源：`风险信号：命中 <信号>（LLM 自判 + jev 复判 P=0.83）/ 仅 jev 命中（自判漏，P=0.75）`——「仅 jev 命中」必须显式说出来，这是复判的核心价值时刻
- jev 全部 P < 0.4 且 LLM 自判也未命中 → 照常播报未命中，附一句「jev 复判未命中（P 均 <0.4）」

## 挂钩点 2 · 卡点根因预判

**消费方**：eo-fix 卡点检查子流程（打地鼠门 / 熔断检查裁决选「卡点检查」时触发——挂在子流程上，不绑裁决门编号）。

**痛点**：现行 spawn 新鲜上下文 subagent 做五分类，是最贵一层；其存在理由是独立性（「修了 3 轮的 agent 是判断自己为何修不好的最差人选」）。jev 结构性满足同一独立性，且便宜一个量级。

**state**：现行 manifest 摘录——change.md §1/§2 + test.md/review.md **未决清单**（失败事实：哪条 FAIL、哪个位置）+ `[<change-id>]` commit 列表（≤120 行节选；**禁止灌报告全史**，同现行纪律）。**不含报告的「结论」与既有根因叙述**——那是复审方的判定，会锚定预判。

**questions**（choice 五选一，criteria 写各根因的可观察特征）：

```json
{
  "root_cause": {"type": "choice", "instructions": "多轮修复未收敛的最可能根因是？", "criteria": {
    "plan_flaw": "change 方案/架构本身不合理，修复只是在错误骨架上打补丁",
    "chain_gap": "链路失败语义残缺：向前写链，恢复面的洞逐次暴露，各轮失败触发位置互不相同",
    "ac_drift": "AC 口径漂移：各轮审查方按不同理解打回，修复方向来回摆",
    "impl_quality": "方案与口径没问题，纯实施质量问题（边界遗漏、低级错误）",
    "infra_flake": "测试基建/环境假失败：断言闪烁、端口/依赖不稳、非业务代码缺陷"
  }}
}
```

**消费**（阈值取自 choice 概率分布）：

- top-1 P ≥ **0.7** 且 top-1 与 top-2 差 ≥ **0.2** → 采纳**根因结论**：一行写入 change.md 末尾 `卡点检查：<根因>（jev 预判，P=<top1>，<版本>），<日期>`，**省掉 subagent**。出口表给的是**建议出口**——与 subagent 结论地位完全相同：豁免一轮 / 回炉 / 全链审查等改变分支的动作仍走各自用户裁决门（熔断三选一 / 打地鼠四选一），jev 不直接授权分支切换
- 阈值不满足 → 回退现行新鲜上下文 subagent 流程（jev 输出可作其输入参考，不预设结论）
- 失败关闭原则不变：subagent 也起不了 → 不得用执行者自述替代，记「卡点检查未执行」，用户三选一裁决
- jev 采纳的预判被后续事实证伪（按该出口走一轮**未收敛**——不限同位失败；错分根因的失败常在新位置出现）→ 视同一次打回，重进卡点检查（此时必走 subagent，不再 jev 预判）

## 明确不挂的判定点（防镀金）

| 判定点 | 不挂理由 |
|--------|----------|
| AC 可验证性逐条判（change-review 维度 1） | reviewer 已是新鲜独立上下文，jev 无独立性增益，只添 API 依赖 |
| trivial 判定（granularity §2） | 四判据大半机械可判，且「判不准按命中」已偏安全侧 |
| 打地鼠信号 / 收敛判定 | 位置列、报告清单机械可判，无判定空间 |
| review finding 定级（P0/P1/P2） | 定级纪律「不确定就降级」已 fail-safe；jev 概率不增加客观性 |

## 校准与演进

- **启用前置 = pin 版本**：`jev-latest` 是漂移别名，阈值（0.7 / 0.4 / 0.2）必须钉在具体版本上才有意义——首次实际启用时按 `jev-cli doctor` 显示的实际模型 `jev-cli config set providers.jev.model jev-<具体版本>` 钉住；别名升级后阈值在新版本上重新校准。播报/转录注明所用版本（溯源与误判复盘依赖）
- 挂钩点的实际命中率与「仅 jev 命中」救场次数，记入 `~/.eo-skills/loop/traps/_general.md`（jev 行为坑也归这里）；连续误判（jev 命中但实为误报 ≥2 次）→ 上调该信号阈值或停用该挂钩点并回修本文件
