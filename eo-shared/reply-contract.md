# 回复契约（长任务收尾汇报）——单一来源

> 被 eo-archive（交付汇报）/ eo-loop（线段收尾报告）/ eo-project-init（agent 配置注入段）引用。目标：长链路收尾时用户一定能看到「做了什么、为什么、去哪验、踩了什么坑」。契约必须有 owner——skill 流程里的硬步骤才算数，只挂在 agent 配置里的被动上下文会被更具体的流程指令挤掉。

## 契约正文

长开发任务收尾时，用一段人话向用户汇报，四条各一句：

1. **做了什么**——行为变化，不是 diff 清单
2. **为什么这么做**——关键决策与理由，被否掉的方案一并点名
3. **主要产出**——文件 / 功能 / 命令，用户去哪看、怎么验
4. **遇到的问题与解法**——没有就明说「无」

受众分两层：对开发者讲接口与路径，对需求方讲行为与结果。一句一事，不铺陈过程。

## 生效通道（两条，互补）

| 通道 | 覆盖场景 | 性质 |
|------|---------|------|
| agent 配置注入段（eo-project-init §9，`eo-reply-contract` 标记） | 非 eo 流程的长任务直改收尾 | 被动上下文，兜底 |
| skill 硬步骤（eo-archive 交付汇报 / eo-loop 线段收尾报告） | eo 流程长链路收尾 | 主动执行，有 owner |

注入段正文必须与「契约正文」逐字一致——改口径只改本文件，init 注入模板整段跟随。

## 与证据面的组合

eo 流程收尾时契约不单独发：与 [evidence.md](evidence.md) 的证据面渲染组合成「交付汇报」，在归档确认提问之前同条消息发出（组合结构以 eo-archive 第一层为准）。
