# 调度经验文件格式（经验沉淀）

根目录 `~/.eo-skills/loop/`（不在仓库内——个人习惯不随 skill 分发，重装 skill 不丢经验）。**分层原则：条目存放在它所属属性的位置**——基底操作坑跟基底走（全项目继承），项目属性跟项目走，收口流水是沉淀原料。

```
~/.eo-skills/loop/
├── preferences/
│   ├── _global.md          跨项目习惯（用户明示跨项目，或同一映射已在 ≥2 个项目文件出现）
│   └── <项目短名>.md        项目属性：节点映射、习惯线段、项目纪律、项目环境陷阱
├── traps/
│   ├── <基底名>.md          该基底的操作陷阱，跨项目全局唯一
│   └── _general.md         基底无关：总控自身操作坑、模型/agent 行为坑
└── history/
    └── <项目短名>.md        收口流水（append-only），保留最近 20 段
```

项目短名取 `.eo-project.json` 的项目名，无则 git 仓库目录名。**短名一致性**：写入前先扫目标目录，存在与目标短名近似的名字（前缀包含或编辑距离 ≤2）时**先核项目身份**——读两个项目的 `.eo-project.json` 项目名与仓库根路径，一致才复用既有名；不一致（foo/food、api/apis 这类真实不同项目）→ 不得合并，列候选走封闭选择，禁止静默并入（历史教训：card-platform / cards-platform 是同项目分裂，但「近似名必同项目」不成立，wow2/wow 会被误并）。

## preferences 文件格式

```markdown
---
scope: global | <项目短名>
updated: YYYY-MM-DD
---

## 节点偏好
- <节点> → <基底> <模型/effort>（YYYY-MM-DD 起；依据：连续 N 次采用 / 用户明示原话）

## 习惯线段
- <入口 → 出口，收敛标准>（YYYY-MM-DD 起）

## 项目纪律
- (YYYY-MM-DD) <用户明示的调度规则，如「每批 change 一组窗口，不跨 change 混用」>

## 项目环境陷阱
- (YYYY-MM-DD) [<环境标签>] <项目特有的坑：端口占用、部署形态、构建工具、本机服务>
```

**体积纪律**：单文件 ≤4KB；超限先合并同根因条目，再按日期淘汰最旧。`_global.md` 覆盖关系：项目文件同名条目优先。

## traps 文件格式

```markdown
# <基底名> 陷阱库

## 已知陷阱
- (YYYY-MM-DD) <坑的记录：什么组合在什么场景失败、处置/降级路径、来源项目>
```

- 条目**不再需要 `[基底名]` 前缀**（文件即归属）；跨基底通用的坑（如「某 agent CLI 不支持启动期选模型」涉及多基底）写 `_general.md` 并在条目内点名涉及基底
- 同根因不同变体的陷阱**合并为一条**，变体列在条目内——同一坑被三个项目分别记三条是分层失败的特征
- 出厂陷阱仍留在基底文件「已知陷阱」节；本库只收运行时新学
- **无对应基底的 traps 文件是孤儿**：`traps/<基底名>.md` 必须对应 `references/substrates/<基底名>.md` 存在才会被读路径消费；基底删除时其运行时陷阱并入 `_general.md`（条目前注明原基底名），不单独留存孤儿文件

## history 文件格式

```markdown
# <项目短名> 收口流水

## YYYY-MM-DD <change-id> 实际生效
- <节点> → <基底 + 模型/effort>（用户显式指定 / 探测选定）
- <本次关键事件一行，如有：打回轮次、熔断裁决、当场纠偏>
```

- **append-only**，新段置顶；超过 20 段裁掉最旧
- 唯一消费场景：聚合判定「连续 ≥2 次同一映射」→ 进 preferences；判定完成后明细即可淘汰

## 读写纪律（与 web-access 站点经验同款）

- **消费必确认**：偏好只用于填补用户本次未指定的空位，且开跑前必须列出命中条目请用户确认（封闭选择：按偏好跑 / 逐项调整），不静默套用；调整结果按纠偏规则回写
- **写入路由**（收口时逐条问「这是谁的属性」）：
  1. 本次映射与事件 → append `history/<项目短名>.md`（单次也写——这是流水，不是偏好）
  2. history 中同一映射连续 ≥2 次 → 聚合进 `preferences/<项目短名>.md` 节点偏好节（注明次数与日期）
  3. 用户明示（「以后 review 都用 X」）→ 直接进 preferences（附原话）；明示跨项目 → `_global.md`
  4. 基底操作坑 → `traps/<基底名>.md`；总控操作坑 / 模型行为坑 → `traps/_general.md`；项目环境坑 → 项目 preferences 文件
  5. 用户当场纠偏 → 立即写入对应层，不等收口
- 条目是**可能有效的提示，不是保证**：按偏好调度失败 → 回退探测，并把失败记入对应 traps 文件
- 用户本次显式指定永远覆盖偏好，且不反写偏好（除非用户说「以后都这样」）
- 每条带日期；更新同一条目刷日期、不新增重复行
