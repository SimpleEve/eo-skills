HOW IT WORKS · 不用先读文档

让变更自己留痕，
让文档自己长出来。

eo-skills 是一套装进 Claude Code / Codex 的开发工作流：你口喷需求和 bug，它负责澄清、验收、实施、归档——代码是唯一真相源，文档是代码的投影，教训会在下次自动回来找你。

01

你要做什么？

整套体系只有三条路。选一个场景，看看会发生什么——注意第一条路：够小的事根本不需要流程。

03

数据怎么轮转

三个循环 + 一层投影。关键只有一句话：所有箭头都是单向的——change 归档后冻结、文档从代码再生、投影永不反写，所以永远不会有两份口径打架。

工件流 · 单程

CHANGE, FROZEN ON ARRIVAL

验收清单（AC）先于代码存在，是 implement 的完成判据、review 的检查表、fix 的期望锚点。归档即冻结——不反写。

文档流 · 再生

DOCS GROW FROM CODE

doc-manager 按 commit 游标增量归档；archive 只是它的触发点之一，直改的提交也会被兜住。代码是唯一信源。

经验流 · 回响

LESSONS COME BACK

教训写成「规则前置 + 触发信号」，下次任务关键词命中 trigger 时自动出现在上下文里——不靠人想起来。

投影层 · OPT-IN

change 的 frontmatter 可以单向投影成 Obsidian 看板卡片（多项目聚合观测）和 GitHub issue / PR（AC 全勾才 Closes）。本地文件永远是唯一真相源，投影只读不回写——GitHub 上关了 issue 而本地没归档？只会收到一行告警。
