三档制：直改 / 轻档 change / 全档 change

不抛 change，也不造新名词——change 分轻 / 全两档（tier: light | full）。轻量化 = 减前置描述、保验收锚点、验证下沉为测试、意图显式去处。

状态 已实施 2026-07-18 · 正文见 docs/tier-design.md
01 · 判档

一次判档，两条底线

判档权在 agent，不在用户

用户始终自然描述需求，agent 判档并一句话宣告（含该档取舍），用户一个词可改档——不新增任何用户决策点，与今天 trivial 短路同一模式。

边界不求精确，只求错得便宜

判不准默认低档，升档路径（promoted）兜底；判高了只多一份工件。两个方向都不产生返工，模糊地带无害。

输入源与档位正交

口述 / backlog 卡 / 外部 GitHub issue / brainstorming 捕获都是输入源，统一过判档门。GH issue 可落任何档（号回写 frontmatter issue:，联动钩子靠它去重）；自带 AC 的输入落盘近乎零成本。

判界写相对量

用「影响面能否圈住」「可审查性」这类相对判据，不写死行数阈值——绝对数字会随模型能力上移而过时。

  1. 测试锁定 = eo-test 前移吸收：实施前把 auto 类 AC 落成失败测试，确认因断言失败（非报错），commit——测试即锁定的规格，实施目标就是让它变绿，无事后测试轮。出现要起环境的重验证（auto-heavy）即扩档信号。负向约束与观感类留书面（人工:）。
  2. 禁改测试：实施中不许动测试文件；AC 本身写错 → 停手上报，改 AC 重锁再继续。
  3. 审查压缩但不砍能力：方案级 → 探针对齐（轻档没有 TODO 映射 / 粒度 / 条件节等审查对象）；代码级 → 完成门的新鲜上下文 subagent 独立复核（AC 覆盖 + 过拟合 / 特判 / 篡改三查，执行者自述不作数）。AC 在 change.md 标准位置，一句「跑 /eo-review」随时升级完整审查，无需扩档。
  4. done 即归档：卡收口后不再编辑，本身即审计记录，无冻结仪式；文档同步走 doc-manager cursor sync 兜底轨（同 trivial 直改），不依赖 archive。INDEX 维护时顺手报告 open 超 30 天未动的卡（防静默蒸发）。

Claude 系模型面对做不到的测试时 79%+ 直接改测试（明确禁止也拦不住）——禁令要配测试锁定 commit 与独立复核。
